# Release notes

## Unreleased
- Added `timeline --format html --output NEW_REPORT.html` for a bounded static offline report from one Linux strace trace or one validated Windows ETW v3 capture. The report retains source-local event evidence, process-link status/basis, source completeness, and diagnostics; filters retain their existing timeline semantics. Output is capped at 64 MiB and published with the protected current-user publisher without replacing an existing file. The renderer escapes source values and uses a restrictive CSP with no scripts or external assets. Synthetic renderer tests cover hostile values, evidence, partial/empty state, CSP, and the output cap; the Linux trace CLI test covers publication and no-clobber behavior. Hosted Linux real-strace tests exercise the timeline adapter. Synthetic Windows ETW CLI tests cover HTML publication and no-clobber behavior. Windows Server 2022/2025 live ETW tests also publish HTML and compare its evidence locator with the JSON result. This remains a single-source view and makes no causal-order or completeness claim.
- Upgraded `sideeffect.event_graph` to schema v6. Native Windows `graph --windows-runtime CAPTURE.json --startup STARTUP.json` can now link exact SCM service `binary_path` matches to decoded ETW process-start image paths as explicitly limited candidate edges. Every edge preserves references to both the startup row and ETW record; duplicate candidates remain separate, event filters are respected, and partial input remains visible. The graph does not claim that a service launched or caused a process. Linux trace graphs continue to work without startup inventory.
- Added Windows startup inventory schema v10 with bounded read-only SCM service trigger configuration from `QueryServiceConfig2W(SERVICE_CONFIG_TRIGGER_INFO)`. The snapshot keeps raw trigger/action/data-type codes alongside reviewed names, optional subtype GUIDs, and trigger-specific bytes encoded as inert hex; each data item is capped at 1,024 bytes, service query buffers at 8 KiB, and aggregate trigger data at 1 MiB. Unsupported, inaccessible, malformed, and over-limit configurations remain unknown with fixed diagnostics. Trigger configuration is not evidence that the event occurred or the service ran. Windows startup diff compares only same-version v10 pairs with observed trigger rows and does not emit raw trigger payloads. Windows `audit --startup` now emits session v15/startup v10 while preserving the v1-v14 artifact contracts.
- Added Windows startup inventory schema v9 with bounded, read-only SCM service dependency MULTI_SZ parsing and separate load-order-group membership from `QueryServiceConfigW`. Dependencies beginning with `+` are recorded as load-order-group references; other values are service-name references. Null/empty dependency data is observed as no dependencies, while malformed, misaligned, unterminated, inaccessible, or over-limit values remain unknown with fixed diagnostics that never echo raw names. The collector does not infer effective startup order, activation, or runtime behavior, and SCM configuration may not reflect a concurrent change to a running service. Windows startup diff compares only fully observed v9 dependency/group fields and suppresses service presence claims for unknown, incomplete, duplicate, or mixed v8/v9 inputs. Linux systemd directive evidence remains raw and is not treated as semantically equivalent. Windows `audit --startup` emits session v14/startup v9; v13/startup v8 and all earlier session artifact allowlists remain readable.
- Added Windows startup inventory schema v8 with a bounded read-only SCM `QueryServiceConfig2W` delayed-auto-start configuration query. Each service reports observed true/false or unknown with a fixed source diagnostic. The bit is ignored by Windows unless service start type is automatic; it does not specify an exact start time or prove execution. Startup diff compares only observed v8 values and suppresses claims for unknown or mixed v7/v8 pairs. Windows `audit --startup` now emits session envelope v13 with startup v8; the reader retains historical v12/startup-v7 compatibility, v10/v11 startup-v6 contracts, v11 App-Paths-only output, and v9 sessions without startup or App Paths.
- Future Linux release builds now inspect the assembled archive's exact file set and bounded member sizes, reject unsafe paths and non-regular entries, extract safely into a fresh runner temporary directory, and run the packaged CLI's `--help` and `version` checks before attestation. Linux, source, and Windows assets are attested in a separate downstream job with OIDC permissions, isolated from build and CLI execution. This workflow validation does not retroactively verify published v0.1.0 or replace native Linux installation acceptance.
- Integrated Windows startup v7 into audit sessions: selecting `audit --startup` emits envelope v12 with startup v7; App Paths remains available in the same session, while App-Paths-only sessions remain v11. Readers preserve the v1-v11 artifact allowlists, v10/v11 accept startup v6 only, and v12 accepts startup v7 only. Session comparison accepts v7/v7 native startup diffs; v6/v7 remains metadata-incomparable and yields a partial native comparison without a service-state delta.

- Added standalone Windows startup inventory schema v7 with a bounded point-in-time SCM service-state observation from `EnumServicesStatusExW`. SCM states 1–7 map to named known values; unsupported raw values remain explicitly unknown. Startup diff accepts v4-v7 and compares service state only when both snapshots carry v7+. This observation is separate from configured startup state and does not imply that a startup entry caused it. That earlier standalone-schema entry is followed by the session-v12 integration recorded above.
- Strengthened the experimental Linux explanation-review workflow with canonical packet hashes and required exact packet-directory verification. The evaluator rejects changed, mismatched, incomplete, duplicate, and unknown packets while continuing to report reviewer identity, input origin, blinding, and independence as unverified. These hashes do not authenticate people or packet origin and do not qualify a model.
- Added standalone Windows startup inventory schema v6 for bounded, read-only permanent WMI event subscription facts from local `ROOT\subscription`: filters, consumers, filter-to-consumer bindings, creator-SID bytes as bounded hexadecimal when available, and exact object references with unresolved-reference status. Uses fixed native WMI COM queries under the current token with explicit packet-privacy proxy security, bounded rows/strings/aggregate text/diagnostics, and no consumer execution or activation. Startup diff and the associated-behavior adapter accept v4-v6 while v4/v5 remain readable. Windows audit-session v1-v9 retain startup v5; selecting `audit --startup` now emits Windows session v10 with startup v6, while sessions without startup and Linux sessions continue to emit v9. Native Windows host smoke and focused reader tests are covered by this change; WMI provider-call duration can exceed the cooperative deadline.
- Added a separate Windows `inventory msix` snapshot for current-user AppX/MSIX registrations and optional Windows audit-session `--msix` source in session schema v9. It retains bounded package identity, version, install-location text, package-type flags, exact UTF-16 evidence, diagnostics, and partial status. It does not query other users, activate packages, inspect package files, or establish availability, health, launchability, or execution. The native Windows CLI/session test passed on build 26300; other Windows client builds remain unvalidated. Hosted Windows Server CI compiles the collector but does not call the package query API.
- Added native Windows App Paths as an optional audit-session v11 source with bounded, hashed item comparisons across verified sessions. Matching uses exact source, hive, registry view, fixed registry key, and UTF-16 subkey evidence; output exposes only hashed values and source/entry references. Incomplete, invalid, or ambiguous identities suppress unmatched presence claims. It does not establish that a registered target exists or can launch.
- Added item-level Windows MSIX registration comparisons to `compare-sessions`. The comparator matches exact valid family-name UTF-16 identities, reports selected version/metadata changes with verified artifact and package-ordinal references, and suppresses unmatched additions/removals for incomplete sources, duplicate identities, or any invalid identity. Registration changes do not establish package availability, health, launchability, or execution; the bounded comparator has synthetic unit and Windows CLI coverage.
- Added a separate Windows `inventory app-paths` snapshot for selected current-user and accessible machine App Paths registry views. Values remain literal and inert; the command does not scan their target paths or establish installation or launchability.
- Upgraded `sideeffect.windows_runtime_attribution` to v2 and its algorithm to v2. Attribution reuses the common raw Kernel-Process v0-v3 PID/parent-PID validator and raw TCP/UDP payload cross-check; unsupported, malformed, truncated, zero-PID, and mismatched process/network rows remain unresolved and mark output partial, with malformed lifecycle rows invalidating active process continuity conservatively. Image names remain untrusted display metadata. Attribution v1 remains historical and is not imported.
- Upgraded the common event envelope, event graph, and event timeline to v4. Native Windows process start/end identity now requires raw Kernel-Process v0-v3 PID/parent-PID bytes to match the serialized TDH sidecar under an exact header pointer-width flag. Unsupported or malformed records remain raw, add bounded diagnostics, invalidate lifecycle continuity, and leave links unresolved. Raw image names remain decoder metadata; ETW loss, PID reuse ambiguity, and non-causal parent-PID semantics are preserved.
- Added native Windows `evidence --windows-runtime` lookup for one ETW event, requiring the validated capture fingerprint, record ordinal, and raw-payload digest to match before returning the event row and source pointer. Partial status and unknown completeness remain explicit; producer authenticity and serialized decode metadata are not verified.
- Upgraded `sideeffect.windows_runtime_diff_summary` to v3 with a field-level ledger for the two fields excluded from exact event equality (`record_ordinal` and `timestamp_qpc`). Both original values are preserved in capture-linked before/after event references. The summary also reports equality of canonical validated capture representation fingerprints, without claiming source JSON byte equality or producer authenticity. Schemas v1-v2 remain historical output formats and are not imported.

## v0.1.0 — Portable skill, Windows runtime evidence, and schema compatibility

### Portable Agent Skill

- Added the `sideeffect-audit` Agent Skill for Codex, Claude Code, OpenCode, and compatible agents, with separate native installation guidance for Oh My Pi (OMP).
- The skill uses the installed deterministic SideEffect CLI and the user's selected agent/model; SideEffect's optional local-model commands are not a prerequisite.
- Added a telemetry-opt-out installer command pinned to the reviewed skill commit, update/removal/privacy guidance, a CI validator for package structure and safety requirements, and a capability-led README with local SVG visuals.
- Release tag [`v0.1.0`](https://github.com/tengircik/SideEffect/releases/tag/v0.1.0) points to main merge commit [`dfff59f`](https://github.com/tengircik/SideEffect/commit/dfff59ffa6ea01995bf121c6c59de9a52ba8ac4c). The [release workflow run 41104218442](https://github.com/tengircik/SideEffect/actions/runs/41104218442) passed all 13 jobs, including Linux and Windows builds, full CI, dependency checks, third-party notice verification, asset checksums, and provenance generation.
- Downloadable Linux x86_64 and Windows x64 archives, a tagged source archive, `SHA256SUMS`, third-party notices, and build-provenance attestations are published. Windows 11 desktop live ETW remains unverified.

### Windows runtime workflows

- Added `attribute --windows-runtime` as a separate evidence-linked view over a validated ETW v3 capture.
- Upgraded `sideeffect.windows_runtime_diff_summary` to v2 with exact normalized record multiset groups, conservative unique-identity candidate groups, one-sided observations, capture-loss details, and source references. Version 1 was an output-only format and is not imported.
- Updated Windows text and HTML comparison reports for event-level output. Reports remain static/offline and use the existing bounded, no-clobber publisher.
- Added a hosted CI step that checks the Windows runner token is already administrative before running the real process/file/loopback ETW acceptance test. SideEffect does not elevate a process.
- Corrected the strict ETW network decoder to accept the exact 4-byte connection-ID layout observed in Windows Server 2022/2025 records with 64-bit event headers. The documented pointer-sized form remains supported; unknown/truncated/trailing layouts remain partial and retain their raw events.
- The v0.1.0 [release workflow](https://github.com/tengircik/SideEffect/actions/runs/41104218442) passed build and live process/file/loopback ETW acceptance on Windows Server 2022 and 2025, as well as Linux, Rust 1.85 MSRV, real Ubuntu `strace`, and Agent Skill installation.
