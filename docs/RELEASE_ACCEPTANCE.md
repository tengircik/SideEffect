This is a fresh-install check only. It does not validate changing PATH entries, updating between distinct released versions, rollback, uninstall, or every supported Windows environment. The v0.1.0 Linux archive remains unexecuted because its attestation could not be verified; a checksum match and safe-looking tar listing do not establish provenance. WSL2 is not native-Linux release acceptance.

The 2026-11-05 repeat `gh attestation verify` attempt for the Windows archive could not initialize the public-good verifier. The 2026-11-06 `gh attestation trusted-root` retry failed with the same Sigstore trusted-root TLS error. The locally computed archive digest matched `SHA256SUMS` and the digest recorded for the Windows archive whose attestation had passed on 2026-11-02; no new attestation verification is claimed for the follow-up.

Future Linux release workflow runs validate the assembled archive's exact member set and bounded sizes before safely extracting it into a fresh runner temporary directory and invoking the packaged CLI's `--help` and `version` commands. A downstream job then attests the smoke-tested Linux archive together with the source and Windows archives; only that job receives OIDC and attestation-write permissions. This improves validation and limits signing privileges for future release builds; it does not retroactively verify or execute the published v0.1.0 archive, and it does not replace installation acceptance on a native Linux system.
