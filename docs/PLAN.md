# SideEffect Delivery Plan

**Status:** implementation is underway; this is not a schedule or release claim. Bounded `inspect`, conservative `diff`, exact-reference `evidence` lookup, terminal-safe text output, Linux-only static HTML export, Linux `record --trace`, and opt-in `record --bundle` plus Linux inspection of strict v1 and v2 bundle formats are implemented. Bundle writing publishes `run.json` and `trace.strace` atomically as one private sibling directory using a no-clobber rename; bundle inspection validates the schema, fixed entries, ownership/modes, size bounds, trace length, and SHA-256 before parsing. A Linux integration test exercises real strace captures of a child's successful `execve`, represented as one complete row or separate continuation rows depending on tracer output, a temporary file operation, and loopback-only TCP activity through record, inspect, and diff; WSL runs used task-local extracted Ubuntu strace packages 6.8 and 6.19, without system installation. The hosted CI run at commit `a6bb3a7a2b2a691f182bf7fbc194f8bb7a703721` passed Linux, Rust 1.85 MSRV, Ubuntu 24.04 strace integration, and Windows jobs on 2026-10-25 (run [40204100065](https://github.com/tengircik/SideEffect/actions/runs/40204100065)); the dependency advisory and declared-license jobs passed on earlier commits. SideEffect's declared strace minimum is 6.8, the lowest version exercised by real-tracer integration; other tracer versions, kernel/distribution combinations, broad syscall coverage, and browser compatibility remain unverified. See the [compatibility and observation matrix](INSTALL.md#compatibility-and-observation-matrix).

## Current implementation slice

The current inventory slice also includes `inventory path-executables` on Linux and native Windows. It snapshots the current process `PATH` (and Windows `PATHEXT`), reads one directory level, uses platform-specific metadata candidate heuristics, preserves ordered exact path encodings and evidence ordinals, and emits bounded partial results without executing files. It is not shell-resolution or launchability validation.


`sideeffect inspect TRACE` reads a regular local file, accepts a bounded subset of `strace` text, preserves raw lines and source byte offsets in a schema-v7 JSON document, and writes that document to stdout. Its `outcome` field is attached only to complete `execve`/`execveat`, `openat`/`openat2`, and `connect` records. It reports `success` only for strict recognized successful results, `failure` only for strict Linux `-1 ERRNO (message)` results, `in_progress` for strict `connect` `EINPROGRESS` results, and `unknown` otherwise. This is a syscall-result summary; raw results and records remain unchanged and authoritative. Unfinished/resumed rows and other syscall names have no outcome field. `sideeffect inspect --bundle DIR` accepts Linux `sideeffect.run` v1 and v2 bundles; recording writes v2, verifies its strict manifest, private fixed files, trace length, and SHA-256 before parsing, and produces the same trace evidence as inspecting the raw trace without including the bundle path. Schema-v2 bundles add `bundle_capture` with the stop reason and optional requested time limit; raw traces and v1 bundles omit it. Timed bundle inspection reports this metadata in JSON/text, warns about incompleteness, and exits 2. The manifest cap is 16 KiB and the trace uses the existing 32 MiB cap. Its `source_sha256` fingerprints the exact bounded byte buffer parsed. For `openat` and `openat2`, it may include an optional `lexical_path_hint` derived from a plain printable-ASCII path and an absolute `-yy` directory annotation; the hint does not query the filesystem, normalize path segments, follow symlinks, or establish descriptor identity. Inspection includes evidence-linked process-creation observations for complete successful `fork`, `vfork`, and qualifying `clone`/`clone3` rows. Schema v7 names the source `caller_task_id`: the `strace -f` prefix identifies a calling task/thread ID, not necessarily the Linux parent PID when a non-leader thread creates a process. The relation connects that caller ID to the child PID returned by the syscall, and is not an OS parent-child claim or a complete process tree. A uniquely paired unfinished/resumed `clone3` may carry both evidence references; `CLONE_PARENT`, thread clones, unpaired calls, and ambiguous relations are omitted with diagnostics. Earlier trace schemas v1-v5 and diff schemas v1-v2 are standalone; schema-v2 bundle inspection carries stop reason and optional time limit in `bundle_capture`, while raw traces and v1 bundles omit it. The CLI reads raw `strace` text only and does not import/migrate prior SideEffect JSON exports. `sideeffect inspect --format text TRACE` writes an ASCII-only terminal-safe view of every parsed, control, and unparsed row plus parser diagnostics and labels any hint as lexical. `sideeffect diff LEFT RIGHT` compares completely parsed raw trace inputs and writes schema-v3 JSON observed deltas with source offsets and separate left/right SHA-256 fingerprints; it includes optional side-specific lexical path hints as display-only fields, while `matching_policy.exact_fields` documents exact row/result comparison and `matching_policy.display_only_fields` explicitly excludes the hints. Fingerprints identify bytes only; they do not authenticate capture or establish completeness. `sideeffect evidence TRACE SHA256 LINE BYTE_OFFSET BYTE_LENGTH` verifies the supplied lowercase fingerprint against the exact parsed bytes before checking the source tuple against exactly one parsed syscall row. Partial input is labeled, and malformed/mismatched fingerprints and control, unparsed, out-of-range, or mismatched tuples are rejected. A successful lookup establishes byte identity relative to the supplied fingerprint and position within those bytes; it does not establish authenticity or capture completeness. Fingerprints are sensitive metadata, can reveal equality, and may be guessable for low-entropy traces; trace bytes are not uploaded. `sideeffect diff --format text LEFT RIGHT` writes a human-readable ASCII-only view with terminal controls escaped and clearly labels path hints as display-only. Linux `sideeffect diff --format html --output REPORT LEFT RIGHT` writes a bounded static offline report, with no scripts or remote assets, mode 0600, and no-clobber publication. It omits local input paths but can contain sensitive trace values. Parser and diff fixtures remain synthetic. The Linux integration test uses the real tracer for a narrow file plus loopback scenario; compatibility with broader tracer output remains unverified.
`sideeffect diff-summary` writes a separate `sideeffect_redacted_diff_summary` schema containing only added/changed/removed diff-group counts by fixed category. Its schema omits syscall names, raw arguments/results, lexical hints, source fingerprints, evidence references, and local input paths. It does not detect secrets or certify that the remaining counts are safe to share. JSON is written to stdout; Linux HTML is capped at 64 MiB, mode 0600, and published without replacing an existing file. This command uploads nothing and is not a redacted detailed diff.

Current hard limits are 32 MiB per input file (64 MiB combined for a diff), 64 KiB per physical record excluding LF, 100,000 records per input, 200,000 diff rows, and 64 MiB for serialized JSON, text, or HTML output. These initial values need review against real captures. `parse_status` describes syntax/continuation parsing only and cannot establish capture completeness. The diff fails closed on partial parses, ignores only parser-level PID/timestamp prefixes when matching, compares exact arguments/results, treats rows as a multiset, and reports excluded control-row counts. It emits a changed row only when exactly one unmatched same-signature record remains on each side; ambiguous result multiplicities remain additions/removals. Before/after references point to the first/second CLI input respectively. Unfinished and resumed rows remain separate observations.

## Product target beyond the current implementation

The product goal is an on-demand, local audit of software on a supported computer. A completed product should combine source-linked software/process inventory, readable permission/configuration facts, startup-hook/script inventory, and observed activity from an explicitly bounded capture. Windows and Linux are first-class product platforms: the same core jobs must be available on both, using native platform sources and clearly documented differences in coverage. Each audit separates configured facts, observed behavior, derived comparisons, and unknowns. Optional local-model commands are not required for the core product. No background daemon or continuous monitoring is part of the target.

Linux x86_64 is the first implemented platform, not the final platform boundary. Native Windows support must provide a useful end-to-end audit in its own right; WSL2 is not Windows coverage. Platform-specific permission and startup mechanisms must be named individually, and the product must not imply identical capture internals or exhaustive coverage. A Linux-only public preview may be labeled as such, but a cross-platform 1.0 release requires the Windows core workflow in Milestones 10–11. The optional local LLM remains a later, opt-in layer that can summarize selected evidence only; it cannot execute commands, change settings, or replace evidence. Cloud inference, telemetry, and automatic privilege escalation remain out of scope.

Milestones 6–12 extend the v0 technical foundation. M6 implements bounded Linux package, process, and selected-path permission snapshots; M7 implements curated Linux startup discovery and narrow evidence-linked candidate correlation. M8's deterministic behavior and optional local-model plumbing are implemented; local-model semantic quality remains unfinished and no model is release-approved. Further M8/local-model work is active under the current project objective and tracked in R9 of [IMPROVEMENT_ROADMAP.md](IMPROVEMENT_ROADMAP.md); it remains optional and does not make the core product depend on a model. The portable Agent Skill in M13 provides a model-independent core workflow through the user's configured agent. M9 bounded session criteria and M10 documented Windows inventory criteria are met for their stated scopes, without authenticating artifacts or claiming exhaustive coverage. M11's bounded native ETW capture, inspection, event-level diff v2, candidate attribution, reports, and live acceptance criteria are verified on hosted Windows Server 2022/2025 at exact source commit [`797ba86`](https://github.com/tengircik/SideEffect/commit/797ba86dc41d024129da35b2fc4be7ad5eca6756) ([CI run](https://github.com/tengircik/SideEffect/actions/runs/40867530573)). M12 schema compatibility, output contracts, producer/adapter round-trip evidence, deterministic mutation exploration, and release compatibility notes are implemented and verified. Windows 11 live ETW and final release review remain open; effective-access analysis and exhaustive coverage are outside the current release scope.

## Milestone 1 — Capture a single run

The first bounded recorder slice is implemented as `sideeffect record --trace OUTPUT -- PROGRAM [ARGS...]`. It sends strace output to a generated private FIFO, enforces the same 32 MiB cap as `inspect`, and publishes a non-empty raw trace only if the output name remains unused. Overflow kills only the direct strace process and discards the staged file. Traces are staged with mode 0600 in a private mode-0700 directory; command stdout/stderr remain inherited. strace introduced `--kill-on-exit` in 6.6, but SideEffect's tested minimum is 6.8; the option is only best-effort cleanup; descendants created with `CLONE_UNTRACED` can escape tracing. Linux integration tests exercise real `strace` capture of successful file and loopback activity, a fixed child process, and a refused loopback connection. The refused-connect case verifies that `ECONNREFUSED` remains a failed syscall attempt and does not become a successful network effect; the evidence reference resolves to the exact raw trace row. The child's successful `execve` may appear as one complete row or as unfinished and matching-PID resumed rows, depending on tracer output; the parser keeps continuation rows separate. The paired diff asserts the observed child row and its evidence reference without reconstructing a logical call. Tests capture command output in memory, check selected fixture sentinels do not appear there, and verify private temp directories are removed. The workflow has no artifact-upload step. Tests fail if `strace` or `python3` is missing; Linux CI installs those packages before running them. WSL integrations passed with extracted, non-installed Ubuntu strace 6.8 and 6.19 packages. These narrow cases do not validate other tracer versions, broad syscall coverage, or all kernel combinations. `--syscall-limit` detaches tracees after a call count and must not be treated as a complete run. Never pass a user-controlled `-o` value directly: strace treats output names beginning with `|` or `!` as commands. See the [`strace(1)` manual](https://man7.org/linux/man-pages/man1/strace.1.html).

- Exercise `record` against a real supported strace version and a harmless shell-free target; confirm the selected option profile and FIFO output behavior.
- Status contract: do not infer target exit outcome or tracer success from the wrapper exit code. `strace` normally mirrors the wrapped command's code/signal; SideEffect labels the value `strace-reported`, inherits runtime stderr diagnostics, and keeps capture completeness unknown even when nonempty trace data exists. Failures that prevent tracer version verification or startup are reported before the target launch. This contract avoids guessing when an internal tracer error cannot be separated from a target outcome.
- Validate cleanup behavior and document that this is not a sandbox and may not terminate descendants that escape tracing.
- Test output caps, no-clobber publication, symlink safety, and cleanup on real tracer startup and termination failures.
- `record --bundle DIR` writes `sideeffect.run` v2 and the exact bounded raw trace as one directory containing only `run.json` and `trace.strace`. Schema v2 adds optional requested duration in milliseconds and a stop reason (`tracer_exited` or `time_limit_reached`); the reader continues to accept v1 and v2. The manifest omits command/program/argv, environment, cwd, username, absolute paths, output streams, tracer diagnostics, and event copies. It records tool/tracer/profile metadata, raw strace status, explicit unverified/unknown outcome markers, and exact trace length/SHA-256. Bundle files are mode 0600 in a mode-0700 directory and publish atomically without replacing an existing path. If an optional duration limit is reached, the available nonempty partial trace is published and CLI status is 2; command outcome and capture completeness stay unknown.
- Follow child processes where the chosen trace mode supports it.
- Keep command status distinct from tracer/parser/report failures.

**Exit criteria:** broader automated real-tracer integration covers a child execution and selected file/network calls; command stdout/stderr and wrapper exit status follow the documented limited contract; missing/unlaunchable tracer conditions fail before the target launch, runtime tracer diagnostics pass through stderr, raw records remain inspectable when produced, and output tests prove existing destinations/symlink targets are not overwritten/followed and failed writes do not publish partial final bundles. Linux integration tests exercise ordinary successful capture, a target exiting with status 37, a target terminated by SIGTERM, inherited target stdout/stderr, and a child `execve` attempt that fails with `ENOENT`, checking that evidence remains inspectable and the trace is published before SideEffect propagates the reported wrapper outcome. A separate fake-tracer contract test checks argument boundaries, inherited diagnostics, inspectable trace output, and the intentionally limited wrapper-status claim; it does not replace real-tracer integration. The capture integration suite passed locally with Ubuntu `strace` 6.19 and in hosted Linux CI, including Ubuntu 24.04 compatibility and Rust 1.85 MSRV jobs. The status contract does not distinguish all tracer-internal errors from target outcomes, and capture completeness remains unknown.

## Milestone 2 — Parse and model evidence

- The initial `inspect` parser supports a bounded `strace_text` outer-record syntax subset; it accepts the current versioned schema. Real output was parsed from strace 6.8 and 6.19. Raw trace text has no reliable tracer-version header, so the parser does not guess or claim the origin version. Bundles record the version queried by SideEffect. Unsupported/malformed rows stay visible as diagnostics and partial status; broader syntax/version coverage is not established.
- The opt-in `record --bundle` writer emits `sideeffect.run` v2, referencing the exact raw trace by fixed bundle filename, byte length, and SHA-256. It records optional duration/stop reason but does not reconstruct events or prove authenticity/completeness. The reader supports v1 and v2; no migration is performed.
- Direct comparison of two validated Linux v1 or v2 bundles is implemented as `diff --bundles LEFT_DIR RIGHT_DIR`; it reuses the strict bundle reader, then applies the existing parser and diff contract. Imported SideEffect JSON remains out of scope.
- Represent process, file, and connection-related observations without overstating success or identity.
- Track parse errors, unsupported records, and detectable incomplete/truncated input.

The parser and renderer must enforce the explicit budgets recorded in Milestone 0. Test each chosen file, record, string, event/collection, comparison, and rendered-output limit at the accepted boundary and just beyond it. Oversized, malformed, and truncated input must not cause unbounded allocation or silent truncation.

**Exit criteria:** fixture tests cover success/failure returns, child processes, conservative lexical path hints and unresolved cwd/dirfd cases, concurrent or unfinished calls, malformed and unsupported records, and evidence-reference integrity. Full filesystem path resolution remains open; unresolved path or process data must remain explicitly unresolved.

## Milestone 3 — Compare two runs

- The first `diff` slice is implemented for completely parsed trace documents. It groups raw syscall rows as a multiset, ignores only parsed PID/timestamp prefixes for matching, compares exact syscall names, arguments, and results, and links deltas to source offsets.
- Control rows are excluded from the initial event comparison, with per-input counts in the JSON output. Unfinished and resumed rows are retained and compared as separate observations rather than reconstructed into logical calls.
- Process/file/network labels are transparent syscall-name buckets, not claims about completed effects. The report says capture completeness is unknown; parser completeness does not establish absence of events.
- Extend matching only with independently justified rules for run-local identities. Keep descriptor/path uncertainty visible and preserve original values in source evidence. Never apply blanket path or file-descriptor normalization.

**Exit criteria:** fixture pairs cover timestamp/PID-prefix changes, added/removed/changed observations, duplicate multiplicity, and unstable event ordering; incomplete input is rejected; every emitted delta links to source evidence; any future normalization is explicit and never destroys raw values. The current exact-argument matcher can still report changes caused by run-local values inside arguments or results; resolve those only through separately reviewed rules.

## Milestone 4 — Export human-readable output and offline HTML

- Versioned JSON diff output is implemented.
- `inspect --format text` is implemented as an ASCII-only listing of every parsed/control/unparsed record and diagnostic. It may show the narrowly scoped lexical path hint; it does not canonicalize paths or infer syscall effects.
- `diff --format text` is implemented as an ASCII-only terminal view; escape trace-derived controls, quotes, backslashes, and non-ASCII scalars and enforce the shared output cap.
- Linux `diff --format html --output REPORT LEFT RIGHT` renders a self-contained offline report with static CSS, no scripts or remote assets, escaped trace-derived content, evidence references, and instructions for checking a cited row with `sideeffect evidence`. Input paths remain omitted; before/after evidence maps to the first/second CLI inputs.
- The HTML report shows comparison context, observed changes, and uncertainty; rendering is capped before no-clobber publication.
- State clearly that reports may contain secrets and are not automatically sanitized; HTML file export is currently Linux-only.

Report generation must enforce the documented event/string/output budgets. Create completed reports atomically without following destination symlinks or replacing existing files; define cleanup behavior for failed or interrupted writes.

**Exit criteria:** schema/round-trip tests pass; HTML tests prove trace-provided markup is inert and no remote assets are required; incomplete captures are conspicuous; the production report limit accepts exactly `MAX_REPORT_BYTES` and rejects one byte over; failed destination-race publication removes staging and preserves source trace bytes. Typed integration round-trips cover inspect schema v7 and diff schema v3 JSON. Renderer tests cover static markup safety and a keyboard skip link/main landmark. Browser compatibility and broad accessibility review remain documented follow-up work; SideEffect does not claim support for all browsers or assistive technologies.

Additional exit criteria: report generation respects documented event/string/output budgets; completed exports are published atomically without following destination symlinks or replacing existing files; a render cap failure and a publication race leave no partial final report and do not corrupt raw run evidence.

- additional Linux architectures or tracing backends, including optional eBPF/audit evaluation;
